# 内测程序打包指南

> 本文档指导如何区分正式程序和内测程序，以及如何打包内测安装包。
> **核心原则：正式程序和内测程序绝对不能混用，必须从源码层面区分。**

---

## 一、正式包 vs 内测包 对比

| 项目 | 正式包 | 内测包 |
|------|--------|--------|
| `IS_BETA_BUILD` | `False` | `True` |
| 版本号 | `2.0.8` | `2.0.8-beta` |
| 启动QQ验证 | 无 | 有（首次启动弹窗） |
| 更新检查通道 | `stable` | `beta` |
| 安装包文件名 | `BilibiliDownloader_x.x.x.exe` | `BilibiliDownloader_Beta_x.x.x.exe` |
| 适用人群 | 所有用户 | 仅授权QQ号用户 |

---

## 二、打包前准备

### 2.1 修改内测标识

打开 `app_config.py`，修改以下两个参数：

```python
# 正式包（默认值）
IS_BETA_BUILD = False
VERSION_NUM = "2.0.8"

# ↓ 打包内测包时改为 ↓
IS_BETA_BUILD = True
VERSION_NUM = "2.0.8-beta"
```

### 2.2 确认云端已配置

1. 登录后台管理 → **内测授权** 页面
2. 在「授权QQ号管理」中添加测试员的QQ号
3. 在「版本管理」中上传内测安装包，通道选择 `beta`

---

## 三、打包步骤

### 3.1 打包内测包

```bash
# 1. 修改 app_config.py
#    IS_BETA_BUILD = True
#    VERSION_NUM = "2.0.8-beta"

# 2. 执行打包命令
pyinstaller --noconfirm --onefile --windowed ^
  --name "BilibiliDownloader_Beta" ^
  --icon "assets/icon.ico" ^
  --add-data "assets;assets" ^
  --add-data "mpv-1;mpv-1" ^
  main.py

# 3. 打包完成后，改回正式标识（非常重要！）
#    IS_BETA_BUILD = False
#    VERSION_NUM = "2.0.8"
```

### 3.2 打包正式包

```bash
# 确认 app_config.py 中：
#   IS_BETA_BUILD = False
#   VERSION_NUM = "2.0.8"

pyinstaller --noconfirm --onefile --windowed ^
  --name "BilibiliDownloader" ^
  --icon "assets/icon.ico" ^
  --add-data "assets;assets" ^
  --add-data "mpv-1;mpv-1" ^
  main.py
```

### 3.3 打包后检查

打包完成后，务必检查 `dist/` 目录下生成的 exe：

1. **内测包**：文件名含 `_Beta`，运行后应弹出QQ授权验证窗口
2. **正式包**：文件名不含 `_Beta`，运行后直接进入主程序

## 四、内测包工作流程

```
内测包启动
    ↓
读取 IS_BETA_BUILD 标识（True）
    ↓
启动 800ms 后自动检查设备码
    ↓
GET /api/v1/beta/?action=auth&client_id=xxx
    ↓
设备码已绑定？
  ├─ 是 → 直接进入主程序（不弹窗）
  └─ 否 → 弹出QQ号输入窗口
              ↓
          用户输入QQ号 → 提交验证
              ↓
          ┌─ QQ号在授权名单？─ 否 → 提示未授权
          ├─ QQ号未绑其他设备？─ 是 → 提示已绑定其他设备
          ├─ 防爆破冷却中？─ 是 → 提示X分钟后重试
          └─ 全部通过 → 绑定设备码 ← QQ号 → 进入主程序
```

## 五、后台管理

### 5.1 授权QQ号管理

路径：后台管理 → **内测授权** → 授权QQ号管理

- **添加QQ号**：单个添加，可填备注
- **批量导入**：每行一个QQ号
- **删除**：移除授权QQ号

### 5.2 设备绑定管理

路径：后台管理 → **内测授权** → 设备绑定管理

- 查看所有已绑定设备（QQ号、设备码、平台、版本、IP、时间）
- **解绑**：解绑后该设备需重新输入QQ号验证

### 5.3 防爆破机制

| 1小时内失败次数 | 冷却时间 |
|-----------------|----------|
| 1~3 次 | 无冷却 |
| 4~6 次 | 5 分钟 |
| 7~9 次 | 30 分钟 |
| 10+ 次 | 24 小时 |

## 六、版本推送说明

### 正式推送

1. 在「版本管理」上传安装包，通道选 `stable`
2. 所有正式包用户都能收到更新通知

### 内测推送

1. 在「版本管理」上传安装包，通道选 `beta`
2. 仅内测包用户能收到更新（正式包不会收到 beta 版本）
3. 内测包启动时检查更新走 `beta` 通道

---

## 七、常见问题

### Q: 打包完内测包后忘记改回正式标识怎么办？

A: 再次打包正式包前，检查 `app_config.py` 中 `IS_BETA_BUILD = False`。如果已经用内测标识打了正式包，重新用正确标识打包即可。

### Q: 测试员换电脑了怎么办？

A: 在后台「设备绑定管理」中找到该QQ号的绑定记录，点击「解绑」。测试员在新电脑上重新输入QQ号即可绑定。

### Q: 测试员输入了错误的QQ号多次怎么办？

A: 防爆破机制会自动冷却。1小时后冷却自动解除，或后台可清理 `beta_auth_log` 表中的失败记录。

### Q: 如何确认一个安装包是内测包还是正式包？

A: 运行安装包，如果弹出QQ授权验证窗口即为内测包，直接进入主程序则为正式包。
